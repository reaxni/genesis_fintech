# Эпизоды Genesis

Каждый каталог в `train/` и `dev/` содержит один эпизод G0 v1.0. В каждом наборе по десять эпизодов. Компании, seed и конфигурации различаются. В обоих наборах есть чистые компании, эпизоды с несколькими ошибками и взаимодействия.

```bash
PYTHONPATH=src python -m genesis_audit.data.corpus --output episodes
```

Запуск с тем же seed, конфигурацией и версией генератора даёт те же байты. Привязки seed к эпизодам заданы в `genesis_audit.data.corpus`. Генератор принимает `scenario` от D01 до D20 или независимые количества четырёх типов ошибок через `errors`. Дополнительные настройки описаны в `src/genesis_audit/data/__init__.py`.

Открытый корпус строится с `profile="diverse"` на генераторе 1.2.0. Seed выбирает отчётный месяц и меняет суммы сценария. Корпус включает пять часовых поясов. Контрольные D01–D20 доступны без профиля, а `profile="stress"` воспроизводит генератор 1.1.0. Все профили используют схему G0 v1.0.

Профиль добавляет независимые счета с одинаковой суммой, оплату в четыре части, два частичных возврата из переплаты и валютные операции по обе стороны полуночи UTC. В D06–D20 от 3 до 5 ошибок. Один из дублей отражён несколькими строками выручки. Сумма, ссылка на исходный счёт и обе группы позволяют его доказать.

У корректных валютных расчётов есть и курсовая прибыль `fx_gain`, и курсовой убыток `fx_loss`. В эпизодах с FX-ошибкой есть корректная операция с той же датой, исходной суммой и валютной парой. Для проверки надо пересчитать поступление по публичному курсу на дату оплаты. [Порядок расчёта](../docs/CONTRACT_G0.md)

Загрузчик политики получает шесть публичных файлов через инструменты среды. `truth.json` и `provenance.json` читает доверенный процесс. В provenance перечислены полные группы строк до и после изменения. Порядок элементов `changes` задаёт порядок применения. `verify_episode` независимо пересчитывает данные и показывает, что откат каждого изменения удаляет одну заявленную ошибку, а исходный журнал согласован.

В платеже отрицательная сумма обозначает возврат переплаты. `invoice_refs` связывает возврат с исходным счётом. В D03 этому счёту соответствует одно входящее поступление с разрешённой переплатой. Сумма возврата списывается с `unapplied_cash`. Фактическое распределение у возврата пустое. Связь читается из полей G0.

Генератор использует арифметику в minor units, локальную дату FX и интервал `[start,end)`. Группы проводок около границы остаются в доступном комплекте, чтобы проверить правильность признания. В контрольном D10 без профиля ожидаемое расхождение совпадает со стартовой фикстурой G0. Во втором поступлении из 70 000 ₸ распределено 20 000 ₸, поэтому недостаёт 50 000 ₸, или 5 000 000 minor units.
