# Genesis FinTech

Genesis — воспроизводимая среда для аудита синтетических компаний. Политика исследует счета, платежи, проводки и курсы. Затем она отправляет найденные расхождения, суммы и ссылки на доказательства. Отдельный оценщик сопоставляет выводы с эталоном.

## Проверка для жюри

Из корня репозитория на Ubuntu с Docker Engine и Docker Compose v2:

```bash
bash scripts/verify.sh
```

Команда собирает два образа Python 3.11.11, запускает тесты и прогоняет четыре политики на 10 train и 10 dev эпизодах. Для первой сборки нужен доступ к базовому образу `python:3.11.11-slim-bookworm` или его локальная копия. Контейнеры проверки работают на CPU с отключённой сетью. Суммарные лимиты сервисов — 2 CPU и 4 ГБ памяти. Сторонних Python-пакетов и API-ключей нет.

| Файл в `artifacts/` | Содержание |
|---|---|
| `trajectories.jsonl` | Шаги закрытых эпизодов. Поля `episode_id`, `step`, `action`, `observation`, `reward`, `terminated`, `truncated`, `policy`. |
| `train_demo.jsonl` | Разбор ошибки в распределении платежа. В train награда видна только на финальном действии. |
| `metrics.jsonl` | По строке на политику и эпизод. Содержит TP/FP/FN, precision, recall, F1, return, число исследований, время и способ завершения. |

Закрытая среда всегда отдаёт политике `reward=0`. Истинные метрики записывает оценщик. Oracle использует эталон как контроль и работает на стороне оценщика.

## Интерфейс жюри

В образе `verify` рабочая директория — `/app`, модуль — `judge_adapter.py`.

| Функция | Результат |
|---|---|
| `generate_episode(seed, config, output_dir)` | Записывает полный эпизод по [форматам G0](docs/CONTRACT_G0.md). |
| `make_env()` | Создаёт среду с `reset` и `step`. |
| `score_episode(episode_dir, findings, inspection_steps)` | Возвращает `tp`, `fp`, `fn`, `precision`, `recall`, `f1` и `return`. |

| Тип вывода | Что подтверждают документы |
|---|---|
| `duplicate_invoice` | Одно обязательство отражено дважды. |
| `payment_allocation` | Часть платежа распределена не по назначению. |
| `fx_conversion` | Пересчёт по указанному курсу даёт другую сумму. |
| `period_cutoff` | Операция признана в неверном отчётном периоде. |

Формат вывода задан в [findings.schema.json](schemas/findings.schema.json). Конфигурации, привязки seed и команда побайтовой пересборки собраны в [описании эпизодов](episodes/README.md).

## Дизайн и демо

Генератор сначала строит согласованную историю, затем вносит ошибки и отдельно сохраняет эталон. Среда выдаёт запрошенные записи через `list_records`, `get_record`, `get_document` и `calculator`. Действие `submit` завершает эпизод. Лимит составляет 100 действий и 60 секунд. Три скриптовые политики работают во втором контейнере и получают только публичные наблюдения по Unix-сокету. Оценщик применяет максимальное взаимно однозначное сопоставление и вычитает стоимость исследований. [Архитектура](docs/ARCHITECTURE.md)

Для короткого демо после прогона открой `artifacts/train_demo.jsonl`. Политика сверяет назначение платежа с фактическим распределением и отправляет сумму и доказательства. Измерения и ограничения перечислены в [отчёте о проверке](docs/ROLE_C_HANDOFF.md).
