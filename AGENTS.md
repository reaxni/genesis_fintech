# Genesis — инструкции для рабочих агентов

## Цель и область
Пользователь поручил прямую подготовку плана и настройку агентов для Genesis FinTech. При реализации по отдельному запуску работай автономно по docs/WORK_PLAN.md и docs/TASKS.md. Готовый план не означает разрешение бесконечно выполнять весь будущий backlog в рамках любого запроса.
Продукт: воспроизводимая RL-среда финансового аудита, генератор синтетических компаний, узкие инструменты расследования, закрытый matcher и проверяемая награда.
Первоисточники: docs/sources/fintech_case_extracted.txt и docs/sources/check_definitions_2026-11-20.txt. Второй текст уточняет транспорт и границы первого. При противоречии не выдумывай новое правило: зафиксируй вопрос в docs/STATUS.md.

## Как начинать
1. Прочти этот файл, docs/STATUS.md, docs/TASKS.md, docs/ARCHITECTURE.md и задачу своей роли.
2. Проверь структуру и git status, если есть Git. Сейчас Git-репозиторий не создан.
3. Возьми одну готовую задачу с закрытыми зависимостями. Координатор — единственный редактор общих контрактов, TASKS и STATUS.
4. Следуй текущему запросу пользователя: прямое поручение выполнять не превращай в учебный опрос. /hint остаётся учебным режимом.

## Обязательные инварианты
- Официальный прогон: Python 3.11, CPU, без сети, платных API и GPU; целевые ограничения 2 CPU, 4 ГБ, 1 ГБ артефактов, 60 секунд на эпизод, 100 действий.
- Все данные синтетические. Деньги: int в minor units, bool запрещён. FX: Decimal из строки. Время: ISO-8601 со смещением; правила периода и округления публичны.
- Сначала согласованная история, потом документы и записанные причинные мутации. Truth не выводится из подозрительности строки.
- Политика — отдельный ограниченный процесс. Ей недоступны episode_dir, seed, truth, provenance, scorer, shell, SQL, сеть, произвольные файлы.
- Скрытие Python-полей и обычный subprocess без ограничения доступа не являются достаточной изоляцией.
- reset с episode_dir загружает именно этот комплект без перегенерации и смены ID.
- Closed reward всегда числовой 0, включая финал; истинные метрики только у оценщика. Train раскрывает только терминальную награду.
- Ошибочный исследовательский вызов расходует шаг. Submit на действии 100 разрешён; submit не входит в inspection_steps. 100 исследований без submit или тайм-аут дают truncated и пустой итог.
- Matcher: сначала структура и исходные лимиты 30/10/1000, затем множества ID; точные строки, полный допустимый набор evidence, любое недоступное evidence => FP. Максимальное паросочетание с официальным детерминированным tie-break.
- Общая reward: clip(2*F1 - 1 - 0.002*inspection_steps, -1, 1). Невалидный submit: -1 и null-метрики на закрытой стороне.
- На чистом эталоне и пустом ответе F1=1, P=R=0. Не меняй формулу ради агента.
- Никаких claims об улучшении обучения без контролируемого held-out сравнения. Oracle не измеряет интеллект политики.

## Делегирование
Роли подготовлены в agent-config/config.toml и agent-config/agents/*.toml. Запись в защищённую .codex отклонена автоматической проверкой разрешений; custom roles не активированы. Используй инструкции ролей через обычный spawn_agent. Модель наследуется от родителя.
Координатор сначала фиксирует интерфейсы; затем параллельно запускает data_engineer, env_engineer, reward_engineer; verifier_engineer подключается после контрактов; reviewer проверяет стабильную интеграцию.
У каждой задачи один владелец файлов. Общие judge_adapter.py, схемы, docs/TASKS.md и docs/STATUS.md меняет только координатор.
Агенты не делегируют дальше. Если среда не поддерживает custom roles, координатор передаёт текст роли через обычный spawn_agent; если нет subagents, выполняет задачи последовательно.
Не создавай новые потоки/процессы только ради занятости. Ожидай зависимости и используй доступную проверку.

## Завершение задачи
Запусти относящиеся к изменению проверки. Отчёт: изменённые файлы, команды, реальные результаты, покрытые ID критериев, известные ограничения, следующий шаг.
Статусы: TODO / IN_PROGRESS / BLOCKED / VERIFIED. VERIFIED допускается только с воспроизводимой командой и отчётом.
Не заявляй прохождение скрытых проверок жюри по локальным аналогам.
Ретроспектива после этапа: факты, сбой и причина, исправление и повторная проверка, следующий риск. Записывай предложения к правилам в docs/RETROSPECTIVE.md; не переписывай AGENTS.md без нового явного поручения.
Ночные и периодические действия сами не запускаются от наличия этого файла; нужна отдельная активная сессия или явно настроенная автоматизация.
