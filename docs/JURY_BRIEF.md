# Genesis · памятка для защиты

## A · Генератор и доказательства

Сначала строим согласованный журнал для синтетической компании. Затем точечно меняем проводки, сохраняя баланс. Скрытый эталон хранит причину, сумму и допустимые доказательства. Независимый верификатор пересчитывает результат по публичным данным и по одному откатывает изменения. При каждом откате должна исчезнуть ровно соответствующая ошибка. Пример для показа — дважды отражённый счёт, у которого вторая группа разбила выручку на строки услуг. Обе группы связаны с одним счётом, и их суммы совпадают.

## B · Среда и изоляция

Политика получает только результаты пяти действий и остаток бюджета. На страницу выдаётся до 50 записей. На эпизод выделено 100 действий и 60 секунд. Калькулятор разбирает десятичную арифметику по ограниченной грамматике. В режиме closed политика всегда видит 0, включая последний шаг. Политика и оценщик работают в отдельных контейнерах. Для проверки реального дедлайна и границ контейнера запустите `bash sandbox/run_isolation_checks.sh`.

## C · Сопоставление и награда

Оценщик проверяет JSON и лимиты, затем ищет совпадения по типу, затронутым ID, сумме, валюте и доказательствам. Каждая находка и каждая эталонная ошибка участвуют максимум в одной паре. Максимальное паросочетание даёт наибольшее число верных находок. Если решений несколько, используется лексикографический порядок пар. Итоговая награда — `clip(2 × F1 − 1 − 0.002 × inspection_steps, −1, 1)`. Oracle проверяет путь через оценщик, а скриптовая сверка показывает результат расследования по доступным данным.

## Проверка на новых эпизодах

Эксперимент автоматически запускается через `bash scripts/verify.sh`. В `artifacts/review_demo.jsonl` записаны 20 тренировочных и 20 отложенных эпизодов профиля `diverse`. Seed открытого корпуса, train и held-out не пересекаются. Генератор использует те же семейства сценариев D01–D20. Суммы, даты, часовые пояса и размеры журналов варьируются.

На каждом train-эпизоде контекстный бандит пробует три порядка чтения и усредняет только терминальные награды среды. Контекст — размер журнала из публичного manifest. После обучения выбор порядков замораживается. Порог размера задан заранее и равен 375 проводкам. На held-out он получает, как и фиксированные порядки, максимум 10 запросов страниц. Правила награды и лимит среды сохраняются.

| Политика на 20 held-out эпизодах | Чтения | TP / FP / FN | Средний return |
|---|---:|---:|---:|
| Фиксированный порядок из базовой сверки | 10 | 33 / 0 / 27 | 0,471 |
| Лучший из трёх фиксированных порядков | 10 | 34 / 0 / 26 | 0,490 |
| Порядок, выбранный после обучения | 10 | 34 / 0 / 26 | 0,490 |
| Базовая сверка | 12,75 | 45 / 0 / 15 | 0,748 |
| Сверка с агрегацией | 12,75 | 60 / 0 / 0 | 0,974 |

**Если спросят, зачем обучение при сильной сверке.** Бандит учится выбирать маршрут расследования при одинаковом бюджете. В эксперименте он добавил одну верную находку относительно исходного порядка и сравнялся с лучшим фиксированным порядком. Бухгалтерские правила у обеих политик одинаковые. Полная сверка читает больше страниц и решает все отложенные случаи. Прогон измеряет перенос на новые значения тех же семейств сценариев.

На отдельном сбалансированном наборе восемь новых эпизодов по двенадцать ошибок, по 24 каждого типа. Обе полные сверки нашли 96 из 96 без ложных находок. В этом наборе ошибки включены независимо. Пропуски базовой сверки на `diverse` связаны с дублями с разной разбивкой.

## Что показать

1. Запустите `bash scripts/verify.sh` из корня проекта.
2. В `artifacts/train_demo.jsonl` покажите последовательность запросов, отправку находки и финальную train-награду.
3. В `artifacts/metrics.jsonl` сравните сверку и oracle на открытом корпусе. Для обсуждения пропусков возьмите повторное признание одного счёта с разной разбивкой выручки.
4. В итоговой строке `artifacts/review_demo.jsonl` покажите выученный выбор порядков и сравнение на held-out.
