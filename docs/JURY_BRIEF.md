# Genesis · памятка для защиты

## A · Генератор и доказательства

Сначала строим согласованный журнал для синтетической компании. Затем точечно меняем проводки, сохраняя баланс. Скрытый эталон хранит причину, сумму и допустимые доказательства. Независимый верификатор пересчитывает результат по публичным данным и по одному откатывает изменения. При каждом откате должна исчезнуть ровно соответствующая ошибка. Пример для показа — дважды отражённый счёт, у которого вторая группа разбила выручку на строки услуг. Обе группы связаны с одним счётом, и их суммы совпадают.

## B · Среда и изоляция

Политика получает только результаты пяти действий и остаток бюджета. На страницу выдаётся до 50 записей. На эпизод выделено 100 действий и 60 секунд. Калькулятор разбирает десятичную арифметику по ограниченной грамматике. В режиме closed политика всегда видит 0, включая последний шаг. Политика и оценщик работают в отдельных контейнерах. Для проверки реального дедлайна и границ контейнера запустите `bash sandbox/run_isolation_checks.sh`.

## C · Сопоставление и награда

Оценщик проверяет JSON и лимиты, затем ищет совпадения по типу, затронутым ID, сумме, валюте и доказательствам. Каждая находка и каждая эталонная ошибка участвуют максимум в одной паре. Максимальное паросочетание даёт наибольшее число верных находок. Если решений несколько, используется лексикографический порядок пар. Итоговая награда — `clip(2 × F1 − 1 − 0.002 × inspection_steps, −1, 1)`. Oracle проверяет путь через оценщик, а скриптовая сверка показывает результат расследования по доступным данным.

## Что показать

1. Запустите `bash scripts/verify.sh` из корня проекта.
2. В `artifacts/train_demo.jsonl` покажите последовательность запросов, отправку находки и финальную train-награду.
3. В `artifacts/metrics.jsonl` сравните сверку и oracle на усложнённом корпусе. Для обсуждения пропусков возьмите сценарий с повторным признанием одного счёта и разной разбивкой выручки.
