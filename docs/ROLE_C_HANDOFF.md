# Передача роли C

## Готово локально

- G0 v1.0: интерфейсы A/B/C, правила типов, evidence, суммы и файловые форматы. Ручной эпизод и ожидаемый ответ доступны в `tests/integration/fixtures/g0_partial_payment/`.
- T04: matcher и награда, лексикографический tie-break, проверка структуры и чисел, доверенный oracle.
- Интеграционная часть: judge adapter, callback среды, Unix JSONL, журнал и отчёт, Dockerfile, Compose и fast/full scripts. Роль B подключается контрактом `AuditEnv` и `choose_action`. GitHub Actions содержит проверку G0 и ручной полный прогон после интеграции A/B.
- Стандартная библиотека обеспечивает runtime и тесты. Этот выбор сделан для проверяемого офлайн-bootstrap при отсутствии доступа к установке зависимостей.
- Исходные команды запуска приведены в README. Порядок трёх PR остаётся в WORK_PLAN.

## Фактическая проверка

На Windows с Python 3.14.3 и `PYTHONPATH=src`:
- `python -B -m unittest discover -s tests/scoring -v` — 4 теста, все прошли. Они включают R01–R20, M01–M12 и сравнение с полным перебором 512 графов.
- `python -B -m unittest discover -s tests/contract_g0 -v` — 1 тест прошёл. Ручная бухгалтерская сумма и публичные доказательства проверены без генератора, среды и оценщика.
- `python -B -m unittest discover -s tests/integration -v` — 8 тестов, 5 прошли и 3 пропущены до появления среды B. Проверены oracle, адаптер с тестовыми двойниками, имитация тайм-аута и ограничение размера сообщений.
- Первый тест IPC завис на `socketpair()` в Windows-сессии. После замены на проверку сериализации и разбора через in-memory stream тест завершился. Это не Linux-тест изоляции.

## Что блокирует релиз

- Контракт и общая фикстура опубликованы в [PR G0](https://github.com/reaxni/genesis_fintech/pull/1). Для входа в `main` нужен review. На момент публикации PR модулей A/B ещё не было.
- Отсутствуют генератор A, его 20 открытых эпизодов и реальная среда/политики B в доступном дереве. Docker не найден, WSL и Git Bash отклоняют запуск в этой сессии. Полный Linux-прогон и проверка изоляции остаются открыты.
- В исходном кейсе требуется лицензия исходников. Финальная лицензия проверяется в общем репозитории до сдачи.

После review и слияния G0 сверить SHA в `main`, затем перевести PR оценщика на `main`. Релиз проверять после подключения A/B. Публикацию и статусы сверять по фактическому SHA.
