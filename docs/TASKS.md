# Очередь реализации
Состояние роли C: T00 опубликован в PR #1, review открыт. T04 проверен локально. Код адаптера, oracle и сборки для T07/T08 подготовлен, полная проверка зависит от A/B и Linux. T09/T11 открыты до проверки общей ветки. Полная матрица — в ACCEPTANCE_MATRIX.md. Фактические команды и ограничения — в ROLE_C_HANDOFF.md.

Для трёх отдельных участников роли таблицы распределяются так: A выполняет data_engineer и verifier_engineer, B — env_engineer и три обычные политики, C — reward_engineer и coordinator. Review делают другие участники по PR. Конкретные пути и стыки описаны в ARCHITECTURE.md.

В T00 входит решение о повторном использовании генератора R3n0va по проверкам из ARCHITECTURE.md. Изменения external generator, fixture и config входят в единый зафиксированный отчёт. В T07 используй чистый и ошибочный парный сценарий для читаемого демо. Эксперимент по обучению опционален после готовности комплекта. Критерий результата — измеренный эффект на замороженных эпизодах.

При конфликте общей схемы: агент останавливает зависимую правку и возвращает конкретное предложение координатору, продолжая независимые тестовые фикстуры.
При дефиците времени: убрать T10 и визуальный viewer, сохранить T00–T09/T11. Не исключать OS-изоляцию, взаимодействия, чистые случаи, парные проверки или matcher tie-break.
Отчёт владельца: ID / файлы / команды / результат / IDs матрицы / оставшийся риск.
